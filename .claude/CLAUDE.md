## Reference project: Riviera

`reference/` (inside this repo, gitignored and excluded from SFTP upload, like `misc/psd/`, the Photoshop sources) holds my previous BGA games, each with its own git history and `.claude/` docs: `reference/riviera/` (Riviera, the model for everything: `reference/riviera/.claude/CLAUDE.md`, `SPEC.md`, `TESTING.md`, `plans/`) and `reference/yaxha/` (Yaxha, the model for the dynamic grid only, not its look: `src/PyramidHandler.ts`, see Layout > Board). **Treat both as read-only.**
**Nexo must be built to look like Riviera's code.** Before creating any file, open the Riviera equivalent and copy its structure, naming, and patterns. When in doubt, do what Riviera does. When Riviera does something a particular way, its `.claude/CLAUDE.md` usually says why; read that before deviating.

Mirror these specifically:

- **Folder layout**: `src/ts/*.ts` and `src/scss/Game.scss` compiled by rollup/sass into `modules/js/Game.js` and `nexo.css`. Same `package.json` scripts, `rollup.config.mjs`, `tsconfig.json`.
- **TS architecture**: one `Game.ts` that owns handler classes, one class per concern in its own file (Nexo's: `BoardHandler`, `BoardRules`, `PlayerHandler`, `TooltipHandler`, `LogMutationObserver`, `EndGameScoringHandler`, `BackgroundHandler`), and client state classes under `src/ts/States/` (`PlaceTowers`, `GameEnd`). `PrefHandler` (Riviera's: `gamepreferences.jsonc` ids by name in `Game.php` `$userPrefs`, sent as `gamedatas.pref_names`, applied at setup and on `bga.userPreferences.onChange`) holds the preferences; a preference that changes the look toggles a class on `<html>` (Riviera's `no-background-drift`), so it also reaches what lives in `<body>` (the flying copies) and the log. Reuse Riviera code as-is only where it is truly game-agnostic (the core of `LogMutationObserver`, the slide animation helpers in `Game.ts`); everything else is adapted.
- **Logs**: same approach as Riviera (see Conventions > Logs).
- **PHP**: namespace `Bga\Games\Nexo` (already set by the template), `Game.php` + `material.inc.php` + a `NEXOTableManager.php` for reading table state (like Riviera's `RIVTableManager.php`), one class per state in `modules/php/States/` using the `GameState` class API like Riviera's.
- **Notifications**: same decorator in the `Game` constructor, same naming style, same way Riviera animates then resolves notifications on the client. Riviera uses `setupPromiseNotifications({ minDuration: 1 })`: BGA's default holds every notification with log text for 500ms even when nothing animates, so a notification lasts exactly as long as its handler awaits a real animation. A handler with no animation must not await anything.
- **DB**: no Deck. A `towers` table, one row per occupied spot (`tower_x`, `tower_y` as signed unbounded integers, `player_id`, `height`), and `player` columns like Riviera's (`reserve`, `passed`). The 5x5 rule is checked from the min and max of x and y. The reserve is a `player` column, not the newer framework's `PlayerCounter`, so only our own notifications update the client.
- **Code style**: tabs/spaces, brace style, camelCase, type annotations, comment style: match Riviera.
- **Framework version**: Nexo's `bga-framework.d.ts` and `_ide_helper.php` are newer than Riviera's (typed `BgaLibraryName` for `importEsmLib` / `getLibUrl`, shared `AddActionButtonParams` / `PerformActionParams`, among others). Before porting a Riviera framework call, check it against Nexo's own copies; a Riviera workaround may no longer be needed.

Each disc sits one `--disc-thickness` above the previous, so only the top face and a band of each disc's edge show. Every disc but the bottom one draws the **seam** between it and the disc below, like the real game's thin gaps, as two 1px box-shadows on its `::after` bottom curve (`.tower-disc + .tower-disc::after`): `--disc-seam-above` just inside the curve, `--disc-seam-below` just under it (`seam-above` / `seam-below` in `$disc-colors`). Red: a lighter edge over a maroon line; black: a dark gap over a grey highlight on the lower disc's rim (a dark line alone doesn't show on black). Kept at every size (the log snapshot's 24px is unchecked). The height as a number sits on the top face (`.tower-height-number`; the reserve stacks have none). A 5-disc tower stays inside its spot, so a tower never covers the spot above it. The face's gradient is centred (`closest-side at 50% 50%`): an off-centre `closest-side` ellipse left a notch on one side.
- **Page background** (`body::before` / `body::after` in `Game.scss`, Riviera's mechanism: `position: fixed` layers at `z-index: -1` inside `body`'s `isolation: isolate`, over BGA's own `html` / `body` background and under the whole page; `body` keeps only the fallback color): a warm white marble surface (`::before`: soft grey veins, clouds, a light top right) under a giant black disc seen up close (`::after`: a window-sized layer cut to a circle by a `radial-gradient` mask with a 1px soft edge, charcoal veins, a sheen and a faint rim light; its soft shadow is a ring just outside the edge on its own layer, `.background-arc-shadow`, a `<div>` `BackgroundHandler` puts first in `<body>` so it paints between the two pseudo-elements: on `::after` the disc's mask would cut it off, and on `::before` it would drift away from the edge). Gradients only, no image. The variables are with the others at the top of `Game.scss` (`$bg-surface-*`, `$bg-disc-*`); the disc's size and position are `$bg-arc-radius`, `$bg-arc-center-x` (from the window's left edge, negative is off-screen) and `$bg-arc-center-y` (below its bottom edge), all in vw, with `$bg-arc-portrait-*` for portrait windows that are not BGA's mobile layout (further down and left). **Mobile** (`body.mobile_version` held upright, 2026-11-17): `$bg-arc-mobile-radius` (320vh), `$bg-arc-mobile-center-x` (-295vh) and `$bg-arc-mobile-center-y` (-30vh: negative puts the centre above the window's bottom edge), in vh because a phone is about twice as tall as wide (the portrait vw values only reached the bottom-left corner): the edge runs up behind the board, about 51% of the width at the bottom, 54% a quarter up and 37% at the top on a 9:19.5 phone (375 x 812, 430 x 932), 42% and 31% on a 375 x 667. A phone held sideways keeps the landscape arc. They reach the layers as custom properties on `body` (`--bg-arc-*`), switched by `@media (orientation: portrait)` (`body`, and `body.mobile_version` inside it, which wins on specificity). Everything of ours over the black (board, log rows) has its own light background.
- **Parallax** (2026-11-17, `BackgroundHandler.ts` and `Game.scss`): scrolling down drifts the page background left, back as it scrolls up, exactly in place at the top. Two depths: the near layer (`body::after`, the black disc, and `.background-arc-shadow`) faster than the far one (`body::before`, the marble and the red disc). **Values to tweak** at the top of `Game.scss`, with the page background's: `$bg-parallax-near-ratio` / `-near-cap` (0.042, 90px) and `$bg-parallax-far-ratio` / `-far-cap` (0.0175, 40px) from `$bg-parallax-mobile-breakpoint` (768px) up, `$bg-parallax-mobile-*` under it (0.035 / 45px, 0.015 / 20px): px of shift per px scrolled, and the most it moves. They reach `:root` as `--bg-parallax-*`; `prefers-reduced-motion` sets the ratios to 0. Each layer moves by `transform: translate3d(--bg-parallax-*-shift)` (`-min(scroll * ratio, cap)`), never `background-position` or `background-attachment: fixed`, and reaches past the window's right edge by its cap plus `$bg-parallax-overscan-margin` (`--bg-parallax-*-overscan`), so no edge shows. Widening a layer would move whatever it places in % of its box, so `overscan-x()` / `overscan-stop()` keep each gradient where it was in a window-sized box (a position across: a share of `100% - overscan`; a `linear-gradient` stop: minus `stop * sin(angle) * overscan`, the gradient line's growth), and the red disc's `right` offset adds the far overscan: at scroll 0 it renders as before, checked headless (no pixel more than 1/255 apart). `BackgroundHandler` (a singleton like Riviera's) only writes `--nexo-parallax` on `<html>`: the page's scroll offset in px, from one passive `scroll` listener, once per frame (`requestAnimationFrame`, `scrollY` read in the frame, not in the listener), clamped at the scroll where the slowest layer reaches its cap (read from `:root` at setup, on `resize` and when `prefers-reduced-motion` changes), and written only when it changes. Moving left never puts black where there was white (the disc's centre is off-screen to the left), so nothing readable ends up over the black.
- **`img/bg_red_disc.png`** (255 x 89, transparent, one red disc with its shadow baked in; the disc is x 12 to 129, y 10 to 86): a decorative red disc in the bottom-right corner, the top layer of `body::before`'s background (so over the marble, under the black disc and the whole page; no element, no clicks). Its disc is `$bg-red-disc-token-ratio` (1.6) times a board tower's disc wide, placed by its centre from the window's right and bottom edges (`$bg-red-disc-right` 17vw, `$bg-red-disc-bottom` 16vh), its bottom edge kept `$bg-red-disc-chatbar-clearance` above the window's bottom. `body::before` can't read the board's inline `--cell-size`, so `BoardHandler.measureForBackgroundDisc()` (run by `fitToViewport()`) sets on `body` the spot size on screen and where the board and player boards are (`--board-cell-screen-size`, `--board-right-gap`, `--panels-right-gap`, `--panels-bottom-gap`, `--board-bottom-gap`); every rule is in `Game.scss`. ## Layout (client)

- **Game area**: only the board (`#nexo-board`), centred in `#nexo-board-container`. No other panel: the player boards' reserves and the status bar show the discs left.
- **Board** (`BoardHandler`), **Yaxha's grid logic** (`reference/yaxha/src/PyramidHandler.ts`, ported as is): `.board-layer` holds `.spots-layer` and `.towers-layer` with every tower and legal spot at its own board coordinates (`--x`, `--y` times `--cell-size`), in a frame anchored to the first tower (0 0) for the whole game, so a tower's grid position never changes; only the layer moves. Like Yaxha's `centerCubesContainer()`, `centerContents()` sets the layer's `translate` so the middle of the bounding box of the towers, the draft's new towers and the legal spots (shown or not, see Draft) sits in the middle of the board. It runs on load (at once: F5, a replay's start), after every draft change (`setDraft()`), and at the end of every turn for every viewer once the towers have landed (`recenter()`, awaited by `notif_towersPlaced`), sliding over `BOARD_RECENTER_DURATION` (280ms `ease-out`; Yaxha's was 400ms) whenever the box's middle moves, whether it grew, shrank or shifted, so the board never drifts off centre; a slide set during another carries on from where the layer is, so nothing jumps. **[BGA] Frozen while drafting** (2026-11-17, unlike Yaxha, which re-centres after each cube): the first drafted tower freezes the centre where it is (`frozenCenter`, set in `setDraft()`), so drafting, cycling, undo and switching the active tower move nothing, even if the draft's new legal spots leave the box off-centre. Players may build on legal spots their own drafted towers open (the server checks the turn as a set), so those spots show at once; if the draft would leave the board (a line of 4 or 5 new towers from the box's edge), `centerContents()` shifts the frozen centre by the least that keeps the whole box on it (the box is never wider than the board, so it always fits). An emptied draft frees it (nothing moves, unless such a shift happened: then it slides back); otherwise `recenter()` frees it once the turn's towers have landed on the frozen layout, then the board slides to its new centre. Unlike Yaxha it computes the box from board coordinates instead of measuring the page, so both players, spectators, a reload and a replay get the very same layout. Nothing else is drawn: no empty spots (no grid dots), no outline of the reachable area. The board is `GRID_SIZE + 2` (7) spots across and down, **as big as the window allows** (`fitToViewport()`: square, from `#nexo-board-container`'s 10px padding under the status bar down to `BOARD_VIEWPORT_MARGIN` (10 screen px) above the window's bottom with the page at its top, then the gap under the board (see Gap under the board) before BGA's settings; never wider than the game area; spots at least `MIN_BOARD_CELL_SIZE` 40px). It sets `--cell-size` inline on `#nexo-board`, so towers, spots and the layer's `translate` scale with it; measured on screen and converted with the container's measured zoom (BGA's mobile scaling). It runs on load, on BGA's `onScreenWidthChange`, on every window `resize` and whenever the page's layout changes (a `ResizeObserver` on `body` and `#page-title`), one per frame, and only touches `--cell-size` when it changed. **BGA is still laying out the page above the game area when `setup()` runs**: measured only then, the board sat too low and stayed about 200px short of the window's bottom on Studio, so anything sized from page measurements must be measured again once the layout settles. The largest box is `GRID_SIZE + 1` (4 columns of towers with a legal spot on each side; with 5, no spot beyond them is legal), checked over 20,000 random games, so it always fits with half a spot to spare. `#nexo-board` clips (`overflow: hidden`). Towers stack in row order (`z-index: y + 1000`) and take no clicks (`pointer-events: none`): clicks go to the spot under them, except on a drafted tower (`.pending-tower`), where a click adds a disc. `.draft-controls-layer` comes after them, over every tower (`$draft-controls-z-index` 2000; `.board-layer`'s `translate` makes it the stacking context, so nothing of BGA's is involved). `fitToViewport()` also sets `--board-zoom` (BGA's measured scaling) on `#nexo-board`, so a size there can keep a minimum in screen px (`max(32px / var(--board-zoom), ...)`).
- **Gap under the board** (2026-11-17): `#nexo-board-container`'s `padding-bottom` keeps the page's background between the board and BGA's own content after the game area (footer, menus, links, table info): `$below-board-gap-share` (40) % of the window's height on desktop, `$below-board-gap-mobile-share` (50) % on `body.mobile_version` (BGA's own switch), variables with the page background's, through `--below-board-gap-share`. In `dvh`, `vh` where `dvh` is unknown. Never less than `100dvh` minus the board's bottom on the page (`--board-page-bottom`, screen px, set on the container by `fitToViewport()`), so with the page at its top that content always starts under the window's bottom: on a phone the board is only as wide (so as tall) as the screen and ends well above its bottom, and the old 10px under it let the footer show at scroll top. Both terms are screen lengths divided by `--bga-game-zoom` (BGA's CSS `zoom` on `#page-content` on a phone scales lengths inside the game area, `vh` included; Riviera's `#game_play_area` `min-height` does the same). Padding, not an element, so nothing in the gap catches a click or a tap. `BOARD_VIEWPORT_MARGIN` (10px) still sizes the board against the window's bottom; it no longer matches the container's bottom padding.
- **Draft** (`States/PlaceTowers.ts`, active player only): `BoardHandler.setDraft()` draws the drafted towers semi-transparent (`.pending-tower`), fades a replaced enemy tower (`.being-replaced`), makes its legal spots clickable (`.legal-spot.clickable-spot`, dashed, solid on hover). Only the player drafting sees legal spots (`renderSpots()` draws no spot at all otherwise, nor in a replay, so nothing looks clickable to the passive player or a spectator): an ellipse ring where the tower's bottom disc would go, in their own disc color (`data-legal-spot-color` on `#nexo-board`, `--legal-spot-*` in `Game.scss`). Shown or not, the legal spots count in the board's centring box for everyone (`getBoxLegalSpots()`: the draft's while drafting, otherwise the board's, the same for every viewer and the same as the draft's when a turn starts, none once the game is over), so the board sits in the same place for both players and doesn't slide when the turn passes. `renderSpots()` also rings each replaceable enemy tower (`.replaceable-spot.clickable-spot`: the legal spots' dashed ellipse in the drafting player's disc color, `--legal-spot-*`, solid on hover, a little wider, around the tower's base and under it) and the drafted tower clicked last (`.selected-spot`, gold, under the tower).
- **Height by clicks** (`PlaceTowers.spotClicked()`, 2026-11-17, replaced the `HeightMenu` popup): a click on a highlighted spot drafts a tower at the lowest height `BoardRules.getHeightOptions()` allows there (1, or the enemy height + 1); a click on a drafted tower adds a disc while `getCycleHeights()` (the same rule, with the tower's own discs counted back among the discs left) allows it, else takes it back (`removePending()`, with `keepConnectedPending()`), so the next click starts again at the lowest. Another spot starts its own tower; the others stay. `BoardHandler.setDraftClickHandlers({ spotClicked, undoClicked, confirmClicked })` routes the board's clicks. The **active tower** is the last clicked one still drafted: `PlaceTowers.clickHistory` lists the drafted towers in the order last clicked, each once (`activate()` on every add or cycle moves it to the top); `update()` drops every tower no longer drafted (undo, a click past its highest, `keepConnectedPending()`), so the one clicked before becomes active again. It is sent as `DraftView.selectedSpot`. `renderPendingControls()` puts, on each drafted tower, a count badge (`.pending-count-badge`, top right, its height, bordered in the player's `--legal-spot-border`; no click: it goes to the tower); only the active tower gets the gold ring and, just under it, `.pending-actions`: a round undo button (`.pending-undo-button`, an inline SVG counter-clockwise arrow, neutral marble, hover like a legal spot's) and a confirm button (`.pending-confirm-button`, a green fill with a white SVG tick: it sends the whole turn). Both are `.pending-button`s, at least `$pending-button-min-size` 32 screen px, `$pending-actions-gap` apart; each `click` listener calls `stopPropagation()`, and `onBoardClick()` ignores any click inside `.pending-actions` (a disabled button's, the gap). The pair stays inside the board in pure CSS: `centerContents()` sets the layer's offsets in spots (`--layer-offset-x/y`), so a `clamp()` nudges it sideways and a `max(0px, overflow) * 1000` step flips it above the tower on the bottom row. Confirm: `PlaceTowers.confirmTurn()` sets `confirming` (both buttons disabled, greyed by a `filter`, never `opacity`: the tower under them would show through; no draft clicks) until `performAction()` rejects (editable again) or `towersPlaced` / the state change clear the draft (`applyPlacements()`, `setDraft(null)`). **No action buttons in the status bar** for this state (no Confirm, no Reset turn): they changed its height and moved the board. No keyboard shortcuts.
- **Turn animation** (`notif_towersPlaced`, `BoardHandler.applyPlacements()`): the turn plays one spot at a time, in the payload's order (the draft's): on a spot, the replaced tower flies back onto its owner's reserve stacks top disc first (`animateTowerSlideAway`, each disc landing on the disc `PlayerHandler.addDiscs()` put there hidden, shown as it lands) while the new tower's discs leave the top of the mover's stacks for the spot, bottom disc first (`animateTowerSlide`, each disc starting exactly over the stack disc `PlayerHandler.takeDiscs()` measured and removed; `Game.getCloneRectOverDisc()` aligns the flying copy's disc on it), its discs `TOWER_DISC_STAGGER` (50ms) apart, and the next spot starts once every disc has landed (`applyPlacement()` returns the spot's flights, awaited together; a spot takes `TOWER_SLIDE_DURATION` plus one stagger per disc above the first). Every viewer sees the same flights, the active player included: a tower they drafted stays as a placeholder (`.confirmed-tower`: no hover, no click) over its faded enemy tower until its spot's turn; then the tower flies in from their stacks like anyone's while the placeholder stays, moved in front of the new tower, and hides each of its discs (the height number with the top one) as the matching solid disc lands on it (`animateTowerSlide`'s `placeholder`), going once the top disc has landed, or at once when nothing flies (until 2026-11-17 it just became solid with no flight, because the state change, and with it `setDraft(null)`, only comes after `towersPlaced`, so the draft is still there when the notification plays). With animations off nothing is awaited, but the stacks still take and get back their discs. Then every reserve is checked against the payload's `reserves` (`setReserve()`, which rebuilds the stacks if they differ), the boards that got discs back bounce, the scores update, then the spots are redrawn and the board re-centres (`recenter()`, see Board). All timings at the top of `Game` (`TOWER_SLIDE_*`, `BOARD_RECENTER_*`).
- **Player boards** (`PlayerHandler`): the reserve, drawn as its discs: 5 stacks of up to 5 discs side by side (`.reserve-stack`, a `.nexo-tower` box of `$reserve-stack-cell-size` with thicker discs, `$reserve-stack-disc-thickness-ratio`, in a box just tall enough for 5 of them, `$reserve-stack-height-ratio`, and a faint dashed outline where its bottom disc goes, so an empty stack stays visible); discs leave from the top of the rightmost non-empty stack and come back onto the top of the leftmost non-full one, so a reserve of n is always the first n slots; `setReserve()` rebuilds the stacks from the count whenever they show anything else (setup, F5, every notification); a tooltip gives the exact count (`TooltipHandler.updateReserveTooltip()`, `addTooltipHtml` again on the same id), and a PASSED stamp (`data-passed`: a grey bordered uppercase label, tilted -6deg, with a forward icon; out of the flow at the row's right end, over the last stacks on a narrow board) after an automatic pass, until the player places again, shown only while exactly one player is passed (`Game.updatePassedStamps()`). Each pass first plays `PlayerHandler.animatePass()`: a `.passed-banner` in `<body>` (the stamp's look at `$passed-banner-scale` through the `passed-stamp-look` mixin, the player's name above it, z-index 1000) pops in at the centre, holds, and flies by its transform onto the board's stamp (measured with its `rotate` off), which it becomes, or fades out where no stamp shows; timings `PASS_BANNER_*` at the top of `Game`. The score is BGA's own counter (the largest group), set through `PlayerHandler.setScore()`. BGA's `.player-board` takes the board's marble and a lighter slab shadow (`#player_boards .player-board`, `$panel-*`).
- **End of the game** (`EndGameScoringHandler`, from `displayEndGameScoring` or gamedatas after F5): `BoardHandler.highlightLargestGroups()` puts a glow under every tower of each player's largest group(s) (light red under red, gold under black, `$largest-group-glow`) and dims every other tower.
- **Logs** (`LogMutationObserver`): "name [board snapshot]" per turn, the pass row, the game end row. The snapshot (`getBoardSnapshotHTML()`, 2026-11-17, replaced the row of one mini tower per placement) is the board after the turn, from `towersPlaced`'s `board_snapshot` (`NEXOTableManager::getBoardSnapshot()`: "x,y" + `r`/`b` + height per tower, space separated, in `preserve`), cropped to the towers' bounding box (`BoardRules.getBounds()`, the main board's coordinates) as a CSS grid of `.snapshot-cell`s with `createTowerDiv` towers (`.snapshot-tower`), a faint dot on empty spots, and a gold ring and glow on the turn's spots (from `placements`). Spots are `$log-snapshot-cell-size` (24px), shrunk only when the row is too narrow (the row is a size container and the snapshot's `--cell-size` is a `min()` over `100cqw`, keeping `$log-snapshot-name-min-width` for the name). A turn logged without `board_snapshot` draws its own towers only. Every row is the board's white marble (`--bg-log-*` from `$log-background-*`) with near-black text, a soft line under it, and a bar on its left edge in its player's disc color: `getDiscColorTag()` adds `red-disc-log` / `black-disc-log` to the row from the notification's args (the mover, the passer, a single winner; a shared victory gets the neutral bar). The bar and the line are box-shadows, so BGA's row layout (timestamps, hover, replay links) is untouched.

## Conventions

Carried over from Riviera because they are framework or BGA facts, not Riviera rules. Add Nexo's own below them.

- **Class prefix**: Nexo's PHP helper classes take the prefix `NEXO` (`NEXOTableManager`, and any later manager the same way). Never port a `RIV` name unchanged.
- **Glossary**: use the terms in SPEC.md > Glossary in code comments, UI strings and docs. If I use a different word for one of them, treat it as the glossary term.
- **Globals** go through `$this->bga->globals`. Throw `\Bga\GameFramework\SystemException`, not the deprecated `\BgaSystemException`.
- **Score display**: use BGA's default score counter (`bga.playerPanels.getScoreCounter(id)`), not a second `ebg.counter`.
- **Scores on the server**: never touch `player_score` / `player_score_aux` with SQL (BGA's deploy check flags it): always go through `$this->bga->playerScore` (`get`, `getAll`, `getMax`, `set`, `setAll`, `inc`; pass `null` as the message when a game notification updates the counter itself). Don't write the column name in comments either.
- **Statistics** go through `$this->bga->playerStats` / `->tableStats`. Initialize every stat in `setupNewGame`, unless leaving one unset on purpose keeps an average honest.
- **Game options** (`gameoptions.jsonc`): each option id is a named constant in `material.inc.php`, with its values as constants too, read with `$this->bga->tableOptions->get($id)`. It returns `null` on a table created before the option existed, so compare against the non-default value and let `null` fall to the default.
- **Logs**: every log type has a `${X_LOG_STR}` server placeholder (plain fallback text as its value, plus `preserve` for the args the row needs), one `LogMutationObserver.createLog*()` method, one `*-log` class, and one `--bg-log-*` variable in `:root` (listed in `$log-types` in `Game.scss`). Only rows that got `a-game-log` show in the game log: one CSS rule hides every other row (BGA's own messages) in `#logs`, the mobile table log (`[id^="chatwindowlogs_zone_tablelog_"]`) and the replay log (`[id^="replaylogs"]`), with `!important` against BGA's inline `display: block`. The chat zones are never touched. So a notification whose log text has no `${X_LOG_STR}` placeholder is invisible. Log rows set their own text color, so BGA's dark mode never lightens it on their pale backgrounds. `bgaFormatText()` has no `args.processed` guard (Riviera's has one): BGA may format the same args twice, and a guarded second pass gives the plain fallback, which that rule hides (a replay from the first move, as black, lost red's first row); every row is built from its args alone, so building it twice is harmless. Decide any per-row styling (the accent bar's color) from the notification's args, never from neighbouring rows: BGA's hidden rows sit between ours, and `#logs` (newest on top) and the mobile/replay logs (oldest on top) run in opposite orders.
- **Slide animations**: one `Game.animateTowerSlide()` / `animateTowerSlideAway()` pair (Riviera's `animateSlide()` / `animateSlideAway()` adapted to towers) for anything flying between the board and a player board. Measure with `getBoundingClientRect()` and move a copy in `<body>` with one `transform` (translate + scale), converting screen px with the copy's own measured zoom (BGA scales the game area on mobile; `offsetWidth` rounds and drifts). The zoom is the rect's width over the **border box's** CSS width: computed `width` is only the content box unless `box-sizing: border-box`, so on anything with padding or a border (the pass banner) it comes out too big and the copy falls short of its target. Never animate `left` / `top`. Layout never jumps when items leave: hold container sizes until the animation ends. Towers fly disc by disc: each disc is a copy of the whole tower with every other disc hidden, so it lands exactly where it sits in the tower.
- **Never put `transform` on an element you later `cloneNode` to animate**: the clone inherits it and every measurement comes out skewed. Use the separate `translate`, `rotate` and `scale` properties.
- **Animations off**: no animation on F5, in fast replay or a hidden tab (`bgaAnimationsActive()` false), or in replays where noted (`isReplay()`); the end state just applies. Anything awaited is raced against a safety timeout so a notification always ends.
- **One-shot animation classes** (fade-ins, fade-outs, value changes) must be removed once they have played: a leftover one becomes the element's fallback `animation` and replays whenever another animation stops applying.
- **Player board bounce**: one shared class and keyframe for every bounce (`.bouncing-player-board`, `0.175s ease-in-out 2`, used when replaced discs land back on a board), added by `PlayerHandler.bounceBoard()`, removed on `animationend`. Never another duration, easing or repeat count, and no TS constants or CSS variables for them.
- **Stacking with BGA**: BGA's fixed status bar is z-index 948, popins 949/950, dialogs 998/999, chat bar and tooltips 2000. A fixed overlay that must sit over the status bar uses 948 and comes later in `<body>`. The flying tower copies (`.sliding-clone`) are 1000.
- **Mobile sizing**: `gameinfos` keeps `game_interface_width.min` at 740, so BGA lays the game out at 740px or more and scales it down on a phone; sizes on `.mobile_version` inside the game area are large logical sizes (`--cell-size` 76px, except on the board, which `fitToViewport()` sizes). Anything fixed in `<body>` (the flying copies, the pass banner) is outside that scaling, so its sizes are real screen px. Inside the board, `--board-zoom` converts a screen-px minimum (the undo button).
- **Tooltips**: Nexo uses BGA's default tooltips (`addTooltip`, `TooltipHandler`). They only reach elements already on the page and need an id on each element; elements the board rebuilds often (spots, drafted towers) get none. Every `.dijitTooltip` is at most `calc(100vw - 16px)` (`Game.scss`).
- **Action buttons** keep BGA's look and `.bgabutton` padding; never give one a height (a recolored one only changes colors). On `.mobile_version`, `#generalactions::before` starts them on a second line under the status bar title. That line is only as tall as BGA's arrow button until a `.bgabutton` joins it, so buttons that come and go within a state change the status bar's height and move the board: `PlaceTowers` has none (its Confirm and undo live on the board). Font Awesome: BGA loads 6.4 as `fa6 fa6-<name>` and 4.7 as `fa`.
- **Zombies** are level 1 (report it in the Game Metadata Manager): every `zombie()` picks a random possible action with `getRandomZombieChoice()` among exactly the buttons a real player would see there (no greedy or "best" choice, no `getBestZombieChoice()`). A zombie that would stay active finishes everything inside the same `zombie()` call, since the framework doesn't call it again.
- **`dbmodel.sql` comments**: put them on their own `--` lines, never after a `;` and never containing a `;`. BGA splits the file into statements itself and silently drops a statement with a trailing comment.
- **Copyright header**: every PHP and TS source file starts with the same header as `Game.php` (BGA checklist).
- **Deleting or renaming PHP files**: SFTP runs with `autoDelete: true`, so a file removed locally is removed on Studio on the next sync. Still check after a delete or rename: the framework loads every class in `modules/php/States/`, and a stale state class collides on its state id (the template's `PlayerTurn.php` takes id 10). **A delete made outside VS Code (`git rm`, `rm` in a terminal) may never reach Studio** (the template's `PlayerTurn.php` stayed there and broke table creation in M1): after any delete or rename, delete the remote file too (SFTP explorer, remote `/nexo/modules/php/States/`) and tell the user to. State ids: SPEC.md > BGA states.
- **No `gameui.isInterfaceLocked()`** in this framework version (Riviera's and Nexo's): use `Game.isInterfaceLocked()`, which reads the `lockedInterface` body class.
- **Rules on both sides**: `NEXOTableManager` holds every board rule and checks the whole turn on confirm; `src/ts/BoardRules.ts` mirrors the rule methods the draft needs (bounds, legal spots, height options, connectivity). Change a rule in both. The server checks a turn as a set (board plus new towers connected, final bounds within the grid), which equals "some order of the towers works", so the client may take any drafted tower back (`keepConnectedPending()`).
- **Turn param**: `actPlaceTowers(#[JsonParam] array $placements, int $activePlayerId)` (`$activePlayerId` is the framework's magic parameter), the client sends `JSON.stringify([{x, y, height}, ...])` (coordinates can be negative).
- **No Undo**: the draft is local to the page (lost on F5) and only the confirm reaches the server, so there is no undo manager on either side; a confirmed turn is final.
- **Replays use the gamedatas saved when the game began**, not a fresh `getAllDatas()`: a field added to `getAllDatas()` later is missing in a replay (`replayFrom`, archives) of a game begun before that deploy, while live tables of the same game have it. Give every newer field a client fallback (`PrefHandler.DEFAULT_PREF_NAMES`: a replay of a game begun before "Show stack heights" crashed in `completesetup`, where BGA calls `userPreferences.onChange`, reading `pref_names.show_stack_heights`).
- **State classes never name a field `args`**: the framework's `StateClass` type has its own `args`, and a private one fails `bga.states.register()`'s type check (`PlaceTowers.stateArgs`).
