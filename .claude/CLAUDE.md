## Reference project: Riviera

`reference/` (inside this repo, gitignored and excluded from SFTP upload, like `misc/psd/`, the Photoshop sources) is my previous BGA game, Riviera, with its own git history and its own `.claude/` docs (`reference/.claude/CLAUDE.md`, `SPEC.md`, `TESTING.md`, `plans/`). **Treat it as read-only.**
**Nexo must be built to look like Riviera's code.** Before creating any file, open the Riviera equivalent and copy its structure, naming, and patterns. When in doubt, do what Riviera does. When Riviera does something a particular way, its `.claude/CLAUDE.md` usually says why; read that before deviating.

Mirror these specifically:

- **Folder layout**: `src/ts/*.ts` and `src/scss/Game.scss` compiled by rollup/sass into `modules/js/Game.js` and `nexo.css`. Same `package.json` scripts, `rollup.config.mjs`, `tsconfig.json`.
- **TS architecture**: one `Game.ts` that owns handler classes, one class per concern in its own file (Nexo's: `BoardHandler`, `BoardRules`, `HeightMenu`, `PlayerHandler`, `TooltipHandler`, `LogMutationObserver`, `EndGameScoringHandler`), and client state classes under `src/ts/States/` (`PlaceTowers`, `GameEnd`). A preferences handler (`PrefHandler`) comes with the first preference. Reuse Riviera code as-is only where it is truly game-agnostic (the core of `LogMutationObserver`, the slide animation helpers in `Game.ts`); everything else is adapted.
- **Logs**: same approach as Riviera (see Conventions > Logs).
- **PHP**: namespace `Bga\Games\Nexo` (already set by the template), `Game.php` + `material.inc.php` + a `NEXOTableManager.php` for reading table state (like Riviera's `RIVTableManager.php`), one class per state in `modules/php/States/` using the `GameState` class API like Riviera's.
- **Notifications**: same decorator in the `Game` constructor, same naming style, same way Riviera animates then resolves notifications on the client. Riviera uses `setupPromiseNotifications({ minDuration: 1 })`: BGA's default holds every notification with log text for 500ms even when nothing animates, so a notification lasts exactly as long as its handler awaits a real animation. A handler with no animation must not await anything.
- **DB**: no Deck. A `towers` table, one row per occupied spot (`tower_x`, `tower_y` as signed unbounded integers, `player_id`, `height`), and `player` columns like Riviera's (`reserve`, `passed`). The 5x5 rule is checked from the min and max of x and y. The reserve is a `player` column, not the newer framework's `PlayerCounter`, so only our own notifications update the client.
- **Code style**: tabs/spaces, brace style, camelCase, type annotations, comment style: match Riviera.
- **Framework version**: Nexo's `bga-framework.d.ts` and `_ide_helper.php` are newer than Riviera's (typed `BgaLibraryName` for `importEsmLib` / `getLibUrl`, shared `AddActionButtonParams` / `PerformActionParams`, among others). Before porting a Riviera framework call, check it against Nexo's own copies; a Riviera workaround may no longer be needed.

## Assets

- No images yet: placeholder art drawn in CSS, every size and color a variable at the top of `src/scss/Game.scss` (`$cell-size`, `$mobile-cell-size`, `$log-cell-size`, `$mini-cell-size`, the disc ratios, `$disc-colors`, the spot and highlight colors). Real disc art would go in `.tower-disc`'s background. When a sprite arrives: one bullet per image here (grid, frame size, frame order, `background-position` from an index, never hardcoded per item; see SPEC.md > Components > Sprite).
- **Towers** (`BoardHandler.createTowerDiv(discColor, height, extraClass)`, the one builder for the board, log rows, player boards and the draft panel): a `.nexo-tower` box exactly one spot (`--cell-size`) whatever its height, so every tower measures the same (`Game.animateSlide` scales by height). Inside, one `.tower-disc` per disc, bottom first, each a cylinder: the top face is the disc's own background (an ellipse in its top `--disc-face-height`), the side a `::before` rectangle and the bottom curve an `::after` ellipse, both at `z-index: -1` inside the disc's `isolation: isolate`. Each disc sits one `--disc-thickness` above the previous, so only the top face and a band of each disc's edge show. The height as a number sits on the top face (`.tower-height-number`, hidden on `.mini-tower`). A 5-disc tower stays inside its spot, so a tower never covers the spot above it. The face's gradient is centred (`closest-side at 50% 50%`): an off-centre `closest-side` ellipse left a notch on one side.
- **Page background** (`body::before` / `body::after` in `Game.scss`, Riviera's mechanism: `position: fixed` layers at `z-index: -1` inside `body`'s `isolation: isolate`, over BGA's own `html` / `body` background and under the whole page; `body` keeps only the fallback color): a warm white marble surface (`::before`: soft grey veins, clouds, a light top right) under a giant black disc seen up close (`::after`: a window-sized layer cut to a circle by a `radial-gradient` mask with a 1px soft edge, charcoal veins, a sheen and a faint rim light; its soft shadow is a ring on `::before` just outside the edge). Gradients only, no image. The variables are with the others at the top of `Game.scss` (`$bg-surface-*`, `$bg-disc-*`); the disc's size and position are `$bg-arc-radius`, `$bg-arc-center-x` (from the window's left edge, negative is off-screen) and `$bg-arc-center-y` (below its bottom edge), all in vw, with `$bg-arc-portrait-*` for portrait windows (further down and left). They reach the layers as custom properties on `body` (`--bg-arc-*`), switched by `@media (orientation: portrait)`. Everything of ours over the black (board, draft panel, height menu, log rows) has its own light background.

## Layout (client)

- **Game area order**, top to bottom: the draft panel (`#draft-panel`), then the board (`#nexo-board`), centred in `#nexo-board-container`.
- **Board** (`BoardHandler`): a window of `2 * GRID_SIZE - 1` (9) spots across and down, always holding every spot the grid can still reach this turn. `.board-layer` holds `.spots-layer` and `.towers-layer` with every spot and tower at its own board coordinates (`--x`, `--y` times `--cell-size`); the layer's inline `translate` brings the window into view. The window is laid on the towers already placed (`computeWindow()`: columns `maxX - 4` to `minX + 4`, centred; an empty board centres on 0 0) and only moves after a turn (`recenter()`, a `translate` transition of `BOARD_RECENTER_DURATION`, set only while recentering), never while drafting, so nothing moves under the cursor. `#nexo-board` clips (`overflow: hidden`), since spots of the old window pass its edge while it slides. Spots outside `BoardRules.getPossibleArea()` (from the towers plus the draft's new towers) are not drawn; `.possible-area` outlines the rest; empty spots show a faint dot. Towers stack in row order (`z-index: y + 1000`) and take no clicks (`pointer-events: none`): clicks go to the spot under them, except on a drafted tower (`.pending-tower`), which a click takes back.
- **Draft** (`States/PlaceTowers.ts`, active player only): `BoardHandler.setDraft()` draws the drafted towers semi-transparent (`.pending-tower`, a hover ×), fades a replaced enemy tower (`.being-replaced`), rings legal spots (`.legal-spot`, teal, dashed then solid on hover), pulses an orange ring around replaceable enemy towers (`.replaceable-spot`, no pulse with reduced motion) and rings the spot waiting for its height (`.selected-spot`, gold). The status bar keeps one title for the whole draft, with Confirm and Reset turn once a tower is drafted. `#draft-panel` (discs left this turn as 5 mini discs: used, left, or beyond the reserve; the reserve after the turn; a hint once a tower is drafted) is hidden with `visibility`, never `display`, so the board never moves when a turn starts or ends.
- **Height menu** (`HeightMenu`, opened and closed only by `PlaceTowers.updateHeightMenu()`, after `setDraft()`): a popup next to the selected spot with one `.height-menu-option` button per legal height, each a tower of that height (`createTowerDiv`, `.height-menu-tower`); a replacement's caption shows the enemy tower and "Replace: at least N discs". It is `position: fixed` in `<body>`, outside BGA's mobile scaling, so its sizes are real screen px (buttons `$height-menu-option-size` 48px, 52px on `.mobile_version`), at `z-index` 948 (over the status bar, under popins). `reposition()` measures the spot on screen, found again by its coordinates (`BoardHandler.getSpotElement()`, since `renderSpots()` rebuilds spot elements on every draft change): above, else below, right, left, then clamped in the viewport and below a fixed `#topbar`, with `--height-menu-arrow-offset` aiming the arrow at the spot. It runs again on scroll (capture, so any scrolling ancestor), resize, `onScreenWidthChange` and after `recenter()`, throttled to one per frame. A `pointerdown` outside the menu dismisses it, except on the board's clickable spots and drafted towers, whose clicks `PlaceTowers` handles (same spot: close; another spot: move; drafted tower: take back), so a click there never closes and reopens it. Escape dismisses; digits pick, ignored while typing in an input (BGA's chat). The anchor gap and edge margin live in `Game.scss` and reach the TS as custom properties (`--height-menu-anchor-gap`, `--height-menu-edge-margin`).
- **Turn animation** (`notif_towersPlaced`, `BoardHandler.applyPlacements()`): the mover's reserve drops at once; each replaced tower flies back to its owner's reserve disc (`animateSlideAway`), each new tower flies from the mover's reserve disc to its spot (`animateSlide`, `TOWER_SLIDE_STAGGER` apart); a tower the active player drafted is already in place and just becomes solid. Then the reserves update, the boards that got discs back bounce, the scores update and the window recentres. All timings at the top of `Game` (`TOWER_SLIDE_*`, `BOARD_RECENTER_*`).
- **Player boards** (`PlayerHandler`): the reserve (a mini disc in the player's color, "× N", dimmed at 0; the flights' start and end point, `getReserveIconElement()`) and a PASSED stamp (`data-passed`: a grey bordered uppercase label, tilted -6deg, with a forward icon) after an automatic pass, until the player places again. The score is BGA's own counter (the largest group), set through `PlayerHandler.setScore()`.
- **End of the game** (`EndGameScoringHandler`, from `displayEndGameScoring` or gamedatas after F5): `BoardHandler.highlightLargestGroups()` puts a glow under every tower of each player's largest group(s) (light red under red, gold under black, `$largest-group-glow`) and dims every other tower.
- **Logs** (`LogMutationObserver`): "name [tower]..." per turn (a replacement as "[enemy tower, faded and crossed] → [tower]" on an orange tint), the pass row, the game end row.

## Conventions

Carried over from Riviera because they are framework or BGA facts, not Riviera rules. Add Nexo's own below them.

- **Class prefix**: Nexo's PHP helper classes take the prefix `NEXO` (`NEXOTableManager`, and any later manager the same way). Never port a `RIV` name unchanged.
- **Glossary**: use the terms in SPEC.md > Glossary in code comments, UI strings and docs. If I use a different word for one of them, treat it as the glossary term.
- **Globals** go through `$this->bga->globals`. Throw `\Bga\GameFramework\SystemException`, not the deprecated `\BgaSystemException`.
- **Score display**: use BGA's default score counter (`bga.playerPanels.getScoreCounter(id)`), not a second `ebg.counter`.
- **Scores on the server**: never touch `player_score` / `player_score_aux` with SQL (BGA's deploy check flags it): always go through `$this->bga->playerScore` (`get`, `getAll`, `getMax`, `set`, `setAll`, `inc`; pass `null` as the message when a game notification updates the counter itself). Don't write the column name in comments either.
- **Statistics** go through `$this->bga->playerStats` / `->tableStats`. Initialize every stat in `setupNewGame`, unless leaving one unset on purpose keeps an average honest.
- **Game options** (`gameoptions.jsonc`): each option id is a named constant in `material.inc.php`, with its values as constants too, read with `$this->bga->tableOptions->get($id)`. It returns `null` on a table created before the option existed, so compare against the non-default value and let `null` fall to the default.
- **Hidden information** (none in the base game; for a later hidden element such as the possible secret bomb): per-player data goes in `getArgs()` as `['_private' => [playerId => [...]]]` and the client reads `args._private`. A secret in a notification goes in one `notify->all()` with `'_private' => [playerId => [...]]` in the args (listed in `preserve`, never merged): each listed player gets only their own part, everyone else, spectators included, gets the args without it; never a `notify->player()` with the secret plus a public twin (two log rows). Public args carry counts, never ids that would tell what a hidden item is.
- **Logs**: every log type has a `${X_LOG_STR}` server placeholder (plain fallback text as its value, plus `preserve` for the args the row needs), one `LogMutationObserver.createLog*()` method, one `*-log` class, and one `--bg-log-*` variable in `:root` (listed in `$log-types` in `Game.scss`). Only rows that got `a-game-log` show in the game log: one CSS rule hides every other row (BGA's own messages) in `#logs`, the mobile table log (`[id^="chatwindowlogs_zone_tablelog_"]`) and the replay log (`[id^="replaylogs"]`), with `!important` against BGA's inline `display: block`. So a notification whose log text has no `${X_LOG_STR}` placeholder is invisible. Decide any per-row styling (group gaps) from the notification's args, never from neighbouring rows: BGA's hidden rows sit between ours, and `#logs` (newest on top) and the mobile/replay logs (oldest on top) run in opposite orders.
- **Slide animations**: one `Game.animateSlide()` / `animateSlideAway()` pair for anything moving between containers (Riviera's). Measure with `getBoundingClientRect()` and move a copy in `<body>` with one `transform` (translate + scale), converting screen px with the copy's own measured zoom (BGA scales the game area on mobile; `offsetWidth` rounds and drifts). Never animate `left` / `top`. Layout never jumps when items leave: hold container sizes until the animation ends.
- **Never put `transform` on an element you later `cloneNode` to animate**: the clone inherits it and every measurement comes out skewed. Use the separate `translate`, `rotate` and `scale` properties.
- **Animations off**: no animation on F5, in fast replay or a hidden tab (`bgaAnimationsActive()` false), or in replays where noted (`isReplay()`); the end state just applies. Anything awaited is raced against a safety timeout so a notification always ends.
- **One-shot animation classes** (fade-ins, fade-outs, value changes) must be removed once they have played: a leftover one becomes the element's fallback `animation` and replays whenever another animation stops applying.
- **Player board bounce**: one shared class and keyframe for every bounce (`.bouncing-player-board`, `0.175s ease-in-out 2`, used when replaced discs land back on a board), added by `PlayerHandler.bounceBoard()`, removed on `animationend`.
- **Stacking with BGA**: BGA's fixed status bar is z-index 948, popins 949/950, dialogs 998/999, chat bar and tooltips 2000. A fixed overlay that must sit over the status bar uses 948 and comes later in `<body>` (the height menu). The flying tower copies (`.sliding-clone`) are 1000.
- **Mobile sizing**: `gameinfos` keeps `game_interface_width.min` at 740, so BGA lays the game out at 740px or more and scales it down on a phone; sizes on `.mobile_version` inside the game area are large logical sizes (`--cell-size` 76px). Anything fixed in `<body>` (the height menu, the flying copies) is outside that scaling, so its sizes are real screen px. `Game.isTouchOrMobile()` (BGA's mobile layout or `(hover: none)`) is the touch check, not BGA's `touch-device` class (a touch laptop with a mouse has it too).
- **Tooltips**: Nexo uses BGA's default tooltips (`addTooltip`, `TooltipHandler`). They only reach elements already on the page and need an id on each element; elements the board rebuilds often (spots, drafted towers) get none. **`addTooltipHtml()` wraps its HTML in a `.midSizeDialog` (500px at most)**. Every `.dijitTooltip` is at most `calc(100vw - 16px)` (`Game.scss`). **An element with a tooltip inside a button**: call `removeTooltip()` on it before the button goes, since no mouseleave comes.
- **Action buttons** keep BGA's look and `.bgabutton` padding; never give one a height (a recolored one only changes colors). Font Awesome: BGA loads 6.4 as `fa6 fa6-<name>` and 4.7 as `fa`.
- **Zombies** are level 1 (report it in the Game Metadata Manager): every `zombie()` picks a random possible action with `getRandomZombieChoice()` among exactly the buttons a real player would see there. A zombie that would stay active finishes everything inside the same `zombie()` call, since the framework doesn't call it again.
- **`dbmodel.sql` comments**: put them on their own `--` lines, never after a `;` and never containing a `;`. BGA splits the file into statements itself and silently drops a statement with a trailing comment.
- **Copyright header**: every PHP and TS source file starts with the same header as `Game.php` (BGA checklist).
- **Deleting or renaming PHP files**: SFTP runs with `autoDelete: true`, so a file removed locally is removed on Studio on the next sync. Still check after a delete or rename: the framework loads every class in `modules/php/States/`, and a stale state class collides on its state id (the template's `PlayerTurn.php` takes id 10). **A delete made outside VS Code (`git rm`, `rm` in a terminal) may never reach Studio**: in milestone 1 the template's `PlayerTurn.php` was removed with `git rm`, stayed on Studio, and table creation failed with "Invalid id for state class ...\States\PlayerTurn (already used by another state)" against `PlaceTowers` (10). After any delete or rename, delete the remote file too (SFTP explorer, remote `/nexo/modules/php/States/`) and tell the user to.
- **State ids**: PlaceTowers 10, NextPlayer 90, EndScore 98 (99 is BGA's game end). The template's `PlayerTurn` (10) is deleted.
- **Rules on both sides**: `NEXOTableManager` holds every board rule and checks the whole turn on confirm; `src/ts/BoardRules.ts` mirrors the rule methods the draft needs (legal spots, height options, reachable area, connectivity, largest groups). Change a rule in both. The server checks a turn as a set (board plus new towers connected, final bounds within the grid), which equals "some order of the towers works", so the client may take any drafted tower back (`keepConnectedPending()`).
- **Turn param**: `actPlaceTowers(#[JsonParam] array $placements)`, the client sends `JSON.stringify([{x, y, height}, ...])` (coordinates can be negative).
- **No Undo**: the draft is local to the page (lost on F5) and only the confirm reaches the server, so there is no undo manager on either side; a confirmed turn is final.
- **State classes never name a field `args`**: the framework's `StateClass` type has its own `args`, and a private one fails `bga.states.register()`'s type check (`PlaceTowers.stateArgs`).
