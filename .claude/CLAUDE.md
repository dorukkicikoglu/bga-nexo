## Reference project: Riviera

`reference/` (inside this repo, gitignored and excluded from SFTP upload, like `misc/psd/`, the Photoshop sources) holds my previous BGA games, each with its own git history and `.claude/` docs: `reference/riviera/` (Riviera, the model for everything: `reference/riviera/.claude/CLAUDE.md`, `SPEC.md`, `TESTING.md`, `plans/`) and `reference/yaxha/` (Yaxha, the model for the dynamic grid only, not its look: `src/PyramidHandler.ts`, see Layout > Board). **Treat both as read-only.**
**Nexo must be built to look like Riviera's code.** Before creating any file, open the Riviera equivalent and copy its structure, naming, and patterns. When in doubt, do what Riviera does. When Riviera does something a particular way, its `.claude/CLAUDE.md` usually says why; read that before deviating.

Mirror these specifically:

- **Folder layout**: `src/ts/*.ts` and `src/scss/Game.scss` compiled by rollup/sass into `modules/js/Game.js` and `nexo.css`. Same `package.json` scripts, `rollup.config.mjs`, `tsconfig.json`.
- **TS architecture**: one `Game.ts` that owns handler classes, one class per concern in its own file (Nexo's: `BoardHandler`, `BoardRules`, `PlayerHandler`, `TooltipHandler`, `LogMutationObserver`, `LogHighlightHandler`, `EndGameScoringHandler`, `BackgroundHandler`, `ConfirmPopover`), and client state classes under `src/ts/States/` (`PlaceTowers`, `GameEnd`). `PrefHandler` (Riviera's: `gamepreferences.jsonc` ids by name in `Game.php` `$userPrefs`, sent as `gamedatas.pref_names`, applied at setup and on `bga.userPreferences.onChange`) holds the preferences; a preference that changes the look toggles a class on `<html>` (Riviera's `no-background-drift`), so it also reaches what lives in `<body>` (the flying copies) and the log. Reuse Riviera code as-is only where it is truly game-agnostic (the core of `LogMutationObserver`, the slide animation helpers in `Game.ts`); everything else is adapted.
- **Logs**: same approach as Riviera (see Conventions > Logs).
- **PHP**: namespace `Bga\Games\Nexo` (already set by the template), `Game.php` + `material.inc.php` + a `NEXOTableManager.php` for reading table state (like Riviera's `RIVTableManager.php`), one class per state in `modules/php/States/` using the `GameState` class API like Riviera's.
- **Notifications**: same decorator in the `Game` constructor, same naming style, same way Riviera animates then resolves notifications on the client. Riviera uses `setupPromiseNotifications({ minDuration: 1 })`: BGA's default holds every notification with log text for 500ms even when nothing animates, so a notification lasts exactly as long as its handler awaits a real animation. A handler with no animation must not await anything.
- **DB**: no Deck. A `towers` table, one row per occupied spot (`tower_x`, `tower_y` as signed unbounded integers, `player_id`, `height`), and `player` columns like Riviera's (`reserve`, `passed`). The 5x5 rule is checked from the min and max of x and y. The reserve is a `player` column, not the newer framework's `PlayerCounter`, so only our own notifications update the client.
- **Code style**: tabs/spaces, brace style, camelCase, type annotations, comment style: match Riviera.
- **Framework version**: Nexo's `bga-framework.d.ts` and `_ide_helper.php` are newer than Riviera's (typed `BgaLibraryName` for `importEsmLib` / `getLibUrl`, shared `AddActionButtonParams` / `PerformActionParams`, among others). Before porting a Riviera framework call, check it against Nexo's own copies; a Riviera workaround may no longer be needed.

- **Parallax** (2026-11-17, `BackgroundHandler.ts` and `Game.scss`): scrolling down drifts the page background left, back as it scrolls up, exactly in place at the top. Two depths: the near layer (`.background-arc`, the black disc and its shadow) faster than the far one (`.background-surface`, the marble); the red disc moves on its own (below). **Values to tweak** at the top of `Game.scss`, with the page background's: `$bg-parallax-near-ratio` / `-near-cap` (0.126, 270px; 0.042 / 90px until 2026-11-18) and `$bg-parallax-far-ratio` / `-far-cap` (0.0175, 40px) from `$bg-parallax-mobile-breakpoint` (768px) up, `$bg-parallax-mobile-*` under it (0.0525 / 68px, until 2026-11-18 0.035 / 45px; 0.015 / 20px): px of shift per px scrolled, and the most it moves. The red disc's: `$bg-parallax-red-disc-ratio` / `-cap` (0.032, 60px; mobile 0.024, 32px; 0.008 / 15px and 0.006 / 8px until 2026-11-18), `$bg-parallax-red-disc-min-scale` (0.7), `$bg-parallax-red-disc-progress-scroll` (2143px; mobile `$bg-parallax-mobile-red-disc-progress-scroll`, 1286px), `$bg-parallax-mobile-red-disc-rise-gap` (8px), `$bg-parallax-mobile-red-disc-rise-factor` (2; 1 until 2026-11-18) and `$bg-parallax-mobile-red-disc-start-margin` (12px, how far inside the board's corner it starts). They reach `:root` as `--bg-parallax-*`, the caps as plain numbers of px (`math.div($cap, 1px)`), like `--nexo-parallax`: the red disc's progress divides the scroll by its progress scroll, and a length divided by a length is too new in CSS, so lengths are made with `* 1px`. `prefers-reduced-motion` sets the ratios to 0 and `--bg-parallax-still` to 1. Each layer moves by `transform: translate3d(--bg-parallax-*-shift)` (`-min(scroll * ratio, cap)`), never `background-position` or `background-attachment: fixed`, and reaches past the window's right edge by its cap plus `$bg-parallax-overscan-margin` (`--bg-parallax-*-overscan`), so no edge shows. Widening a layer would move whatever it places in % of its box, so `overscan-x()` / `overscan-stop()` keep each gradient where it was in a window-sized box (a position across: a share of `100% - overscan`; a `linear-gradient` stop: minus `stop * sin(angle) * overscan`, the gradient line's growth), and the red disc's `right` offset adds the far overscan: at scroll 0 it renders as before, checked headless (no pixel more than 1/255 apart). `BackgroundHandler` (a singleton like Riviera's) puts `.background-surface`, `.background-red-disc` then `.background-arc` first in `<body>`, and only writes `--nexo-parallax` inline on each of those three: the page's scroll offset, a plain number of px, from one passive `scroll` listener, once per frame (`requestAnimationFrame`, `scrollY` read in the frame, not in the listener), clamped at the scroll where the slowest layer reaches its cap (read from `:root` at setup, on `resize` and when `prefers-reduced-motion` changes), and written only when it changes (compared with the last value written, not read back). **Smooth on a phone** (2026-11-27, it ran at a low frame rate): until then `--nexo-parallax` was set on `<html>`, so every frame the browser recomputed the style of every element of BGA's page (a custom property inherits everywhere); now only the three layers restyle. Each is exactly one composited layer (`will-change: transform` on those three only, none on their pseudo-elements), moved only by `transform`, with no `filter`, `box-shadow`, `backdrop-filter` or blend mode, so its gradients and mask are painted once and scrolling only moves them. Only the formulas that read `--nexo-parallax` (each layer's `--bg-parallax-*-shift`, the red disc's `-progress` and `-scale`) are declared on the layers (`parallax-layer-shift()` in `Game.scss`): a `var()` resolves where it is declared, so on `:root` they would ignore the layers' value. Checked headless against the old version at offsets 0 to 4000, desktop and 390px: identical but for at most 4/255 along the black disc's edge (the shadow and the disc now blend in one layer). The marble is a third moving layer: freezing it would save a layer but drop its drift. ## Conventions

Carried over from Riviera because they are framework or BGA facts, not Riviera rules. Add Nexo's own below them.

- **Class prefix**: Nexo's PHP helper classes take the prefix `NEXO` (`NEXOTableManager`, and any later manager the same way). Never port a `RIV` name unchanged.
- **Glossary**: use the terms in SPEC.md > Glossary in code comments, UI strings and docs. If I use a different word for one of them, treat it as the glossary term.
- **Globals** go through `$this->bga->globals`. Throw `\Bga\GameFramework\SystemException`, not the deprecated `\BgaSystemException`.
- **Score display**: use BGA's default score counter (`bga.playerPanels.getScoreCounter(id)`), not a second `ebg.counter`.
- **Scores on the server**: never touch `player_score` / `player_score_aux` with SQL (BGA's deploy check flags it): always go through `$this->bga->playerScore` (`get`, `getAll`, `getMax`, `set`, `setAll`, `inc`; pass `null` as the message when a game notification updates the counter itself). Don't write the column name in comments either.
- **Statistics** go through `$this->bga->playerStats` / `->tableStats`. Initialize every stat in `setupNewGame`, unless leaving one unset on purpose keeps an average honest.
- **Game options** (`gameoptions.jsonc`): each option id is a named constant in `material.inc.php`, with its values as constants too, read with `$this->bga->tableOptions->get($id)`. It returns `null` on a table created before the option existed, so compare against the non-default value and let `null` fall to the default.
- **Logs**: every log type has a `${X_LOG_STR}` server placeholder (plain fallback text as its value, plus `preserve` for the args the row needs; the end-of-game replay / game review page shows only that fallback, so it must identify the move on its own: `TOWERS_PLACED_LOG_STR` gives each tower's height and spot, "2 at (0,-1), 3 at (1,0) replacing 2", in `cellKey()`'s x,y), one `LogMutationObserver.createLog*()` method, one `*-log` class, and one `--bg-log-*` variable in `:root` (listed in `$log-types` in `Game.scss`). Only rows that got `a-game-log` show in the game log: one CSS rule hides every other row (BGA's own messages) in `#logs`, the mobile table log (`[id^="chatwindowlogs_zone_tablelog_"]`) and the replay log (`[id^="replaylogs"]`), with `!important` against BGA's inline `display: block`. The chat zones are never touched. So a notification whose log text has no `${X_LOG_STR}` placeholder is invisible. Log rows set their own text color, so BGA's dark mode never lightens it on their pale backgrounds. `bgaFormatText()` has no `args.processed` guard (Riviera's has one): BGA may format the same args twice, and a guarded second pass gives the plain fallback, which that rule hides (a replay from the first move, as black, lost red's first row); every row is built from its args alone, so building it twice is harmless. Decide any per-row styling (the accent bar's color) from the notification's args, never from neighbouring rows: BGA's hidden rows sit between ours, and `#logs` (newest on top) and the mobile/replay logs (oldest on top) run in opposite orders.
- **Slide animations**: one `Game.animateTowerSlide()` / `animateTowerSlideAway()` pair (Riviera's `animateSlide()` / `animateSlideAway()` adapted to towers) for anything flying between the board and a player board. Measure with `getBoundingClientRect()` and move a copy in `<body>` with one `transform` (translate + scale), converting screen px with the copy's own measured zoom (BGA scales the game area on mobile; `offsetWidth` rounds and drifts). The zoom is the rect's width over the **border box's** CSS width: computed `width` is only the content box unless `box-sizing: border-box`, so on anything with padding or a border (the pass banner) it comes out too big and the copy falls short of its target. Never animate `left` / `top`. Layout never jumps when items leave: hold container sizes until the animation ends. Towers fly disc by disc: each disc is a copy of the whole tower with every other disc hidden, so it lands exactly where it sits in the tower.
- **Never drive a per-frame animation through a custom property on `<html>` or `<body>`** (2026-11-27, the parallax): it inherits into every element, so each change restyles BGA's whole page. Set it inline on the moving element itself, declare whatever `var()` reads it on that element, and move it by `transform` only.
- **Never put `transform` on an element you later `cloneNode` to animate**: the clone inherits it and every measurement comes out skewed. Use the separate `translate`, `rotate` and `scale` properties.
- **Animations off**: no animation on F5, in fast replay or a hidden tab (`bgaAnimationsActive()` false), or in replays where noted (`isReplay()`); the end state just applies. Anything awaited is raced against a safety timeout so a notification always ends.
- **One-shot animation classes** (fade-ins, fade-outs, value changes) must be removed once they have played: a leftover one becomes the element's fallback `animation` and replays whenever another animation stops applying.
- **No player board bounce** (removed 2026-11-26 at the user's request): a reserve that gets discs back from a replacement doesn't bounce; its discs' flights back are the only animation. Until then one shared `.bouncing-player-board` (`PlayerHandler.bounceBoard()`, `0.175s ease-in-out 2` on `top`) bounced BGA's `.player-board`, then the `.top-bar-player` side. Don't bring it back without asking.
- **Stacking with BGA**: BGA's fixed status bar is z-index 948, popins 949/950, dialogs 998/999, chat bar and tooltips 2000. A fixed overlay that must sit over the status bar uses 948 and comes later in `<body>` (the "Confirm anyway?" card). The flying tower copies (`.sliding-clone`) are 1000.
- **Mobile sizing**: `gameinfos` keeps `game_interface_width.min` at 740, so BGA lays the game out at 740px or more and scales it down on a phone; sizes on `.mobile_version` inside the game area are large logical sizes (`--cell-size` 76px, except on the board, which `fitToViewport()` sizes). Anything fixed in `<body>` (the flying copies, the pass banner) is outside that scaling, so its sizes are real screen px. Inside the board, `--board-zoom` converts a screen-px minimum (the undo button).
- **Tooltips**: Nexo uses BGA's default tooltips (`addTooltip`, `TooltipHandler`). They only reach elements already on the page and need an id on each element; elements the board rebuilds often (spots, drafted towers) get none. Every `.dijitTooltip` is at most `calc(100vw - 16px)` (`Game.scss`).
- **Action buttons** keep BGA's look and `.bgabutton` padding; never give one a height (a recolored one only changes colors). **No forced line break in the status bar** (2026-11-18, differs from Riviera): Riviera's `.mobile_version #generalactions::before { content: ""; display: block; }` acts like a `<br>` before `#generalactions` (an inline box), so on mobile it pushed BGA's arrow button onto a second line under the title even with room to spare (the bar about 69px instead of 45px on a mock). Nexo has no such rule: the title, the disc icons and `#generalactions` (the arrow button, any `.bgabutton`) flow inline on one line and wrap naturally when they don't fit. Buttons that come and go within a state would still change the status bar's height and move the board: `PlaceTowers` has none (its Confirm and undo live on the board). Font Awesome: BGA loads 6.4 as `fa6 fa6-<name>` and 4.7 as `fa`.
- **Zombies** are level 1 (report it in the Game Metadata Manager): every `zombie()` picks a random possible action with `getRandomZombieChoice()` among exactly the buttons a real player would see there (no greedy or "best" choice, no `getBestZombieChoice()`). A zombie that would stay active finishes everything inside the same `zombie()` call, since the framework doesn't call it again.
- **`dbmodel.sql` comments**: put them on their own `--` lines, never after a `;` and never containing a `;`. BGA splits the file into statements itself and silently drops a statement with a trailing comment.
- **Copyright header**: every PHP and TS source file starts with the same header as `Game.php` (BGA checklist).
- **Deleting or renaming PHP files**: SFTP runs with `autoDelete: true`, so a file removed locally is removed on Studio on the next sync. Still check after a delete or rename: the framework loads every class in `modules/php/States/`, and a stale state class collides on its state id (the template's `PlayerTurn.php` takes id 10). **A delete made outside VS Code (`git rm`, `rm` in a terminal) may never reach Studio** (the template's `PlayerTurn.php` stayed there and broke table creation in M1): after any delete or rename, delete the remote file too (SFTP explorer, remote `/nexo/modules/php/States/`) and tell the user to. State ids: SPEC.md > BGA states.
- **No `gameui.isInterfaceLocked()`** in this framework version (Riviera's and Nexo's): use `Game.isInterfaceLocked()`, which reads the `lockedInterface` body class.
- **Rules on both sides**: `NEXOTableManager` holds every board rule and checks the whole turn on confirm; `src/ts/BoardRules.ts` mirrors the rule methods the draft needs (bounds, legal spots, height options, connectivity, and the score: `getLargestGroupSize()`, for the scoreboard's previews). Change a rule in both. The server checks a turn as a set (board plus new towers connected, final bounds within the grid), which equals "some order of the towers works", so the client may take any drafted tower back (`keepConnectedPending()`).
- **Turn param**: `actPlaceTowers(#[JsonParam] array $placements, int $activePlayerId)` (`$activePlayerId` is the framework's magic parameter), the client sends `JSON.stringify([{x, y, height}, ...])` (coordinates can be negative).
- **No Undo**: the draft is local to the page (lost on F5) and only the confirm reaches the server, so there is no undo manager on either side; a confirmed turn is final.
- **Replays use the gamedatas saved when the game began**, not a fresh `getAllDatas()`: a field added to `getAllDatas()` later is missing in a replay (`replayFrom`, archives) of a game begun before that deploy, while live tables of the same game have it. Give every newer field a client fallback (`PrefHandler.DEFAULT_PREF_NAMES`: a replay of a game begun before "Show stack heights" crashed in `completesetup`, where BGA calls `userPreferences.onChange`, reading `pref_names.show_stack_heights`).
- **State classes never name a field `args`**: the framework's `StateClass` type has its own `args`, and a private one fails `bga.states.register()`'s type check (`PlaceTowers.stateArgs`).
